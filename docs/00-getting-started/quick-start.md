# Quick Start Guide

> **For AI Agents** - Essential information to start working on Enter365 immediately.

---

## What is Enter365?

**Enter365** is a Laravel 12 ERP/Accounting system for Indonesian SMEs specializing in:
- **Electrical panel manufacturing** - Custom panel builders with multi-brand BOM alternatives
- **Solar EPC contracting** - Solar installation projects with ROI proposals

**Accounting Standard:** SAK EMKM (Indonesian MSME accounting standard)

### Layer Structure

```
app/
├── Http/
│   ├── Controllers/Api/V1/    # Thin controllers (HTTP concerns only)
│   ├── Requests/Api/V1/       # Form Request validation
│   └── Resources/Api/V1/      # API response transformation
│
├── Services/{Domain}/         # Business logic layer (77 services)
│
├── Domain/{Domain}/           # DDD patterns (StateMachines, Events, ValueObjects)
│
├── Contracts/{Domain}/        # Interfaces (40+ contracts)
│
├── Models/{Domain}/           # Eloquent models (71 models)
│
├── Filters/                   # Query filters for API endpoints
│
└── Infrastructure/
    ├── Events/                # Event dispatchers
    └── Listeners/             # Event listeners
```

## Key Patterns You'll Encounter

### 1. State Machines (Document Workflows)

Documents use StateMachines for state transitions:

```php
// In service
$stateMachine = InvoiceStateMachine::fromInvoice($invoice);
$stateMachine->transitionTo(DocumentStatus::Sent);
```

**Location:** `app/Domain/{Domain}/{Entity}/{Entity}StateMachine.php`
**Docs:** `/docs/07-code-patterns/state-machine-pattern.md`

### 2. Service Layer (Business Logic)

All business logic lives in services, not controllers:

```php
// Controller (thin)
public function store(StoreInvoiceRequest $request, InvoiceServiceInterface $service)
{
    $invoice = $service->create($request->validated());
    return InvoiceResource::make($invoice);
}

// Service (business logic)
public function create(array $data): Invoice
{
    return DB::transaction(function () use ($data) {
        // All business logic here
    });
}
```

**Location:** `app/Services/{Domain}/`
**Docs:** `/docs/07-code-patterns/service-pattern.md`

### 3. Query Filters (API Filtering)

List endpoints use filter classes:

```php
// Controller
public function index(InvoiceFilter $filter)
{
    return Invoice::query()->filter($filter)->paginate();
}

// API: /api/v1/invoices?status=sent&search=INV-2024
```

**Location:** `app/Filters/`
**Docs:** `/docs/07-code-patterns/filter-pattern.md`

### 4. Domain Events (Side Effects)

Events decouple side effects:

```php
// StateMachine fires event
$this->eventDispatcher->dispatch(InvoiceSent::fromInvoice($invoice));

// Listener handles side effect
class PostInvoiceToJournal {
    public function handle(InvoiceSent $event) { /* ... */ }
}
```

**Location:** `app/Domain/{Domain}/{Entity}/Events/`, `app/Infrastructure/Listeners/`
**Docs:** `/docs/07-code-patterns/event-listener-pattern.md`

```php

            // ...
        });
    });

            // ...
        });

```

**Run related tests after changes:**

```bash

```

## API Conventions

- **Versioned:** All routes under `/api/v1/`
- **RESTful:** Standard resource routes
- **Pagination:** 25 items/page default
- **Filtering:** Via query parameters (`?status=sent&search=...`)
- **Sorting:** `?sort=field&direction=asc|desc`

**OpenAPI spec:** `/api.json` (generated by Scramble)
